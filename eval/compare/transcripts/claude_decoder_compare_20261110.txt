      I ran PyMatching and Tesseract directly. CUDA-Q Relay-BP wouldn’t run here because this
      workspace has no NVIDIA GPU ( ERROR: No GPU is available ). In its place I ran IBM’s
      open-source CPU version of Relay-BP (the relay-bp package), which uses the same
      algorithm and the same relay settings.
      Setup: Stim color_code:memory_xyz , d=5, 5 rounds, uniform circuit-level noise at p=0.002
      (45 detectors, 1104 error mechanisms). All decoders got the same 2000 shots, sampled with
      seed 42. 1284 of those shots had at least one detection event.

      What the results show:
             Tesseract has the lowest error rate. The gap to Relay-BP is not statistically significant at
             2000 shots, though (Fisher exact test p ≈ 0.15). You’d need roughly 20k or more shots to
             separate them with confidence.
             Relay-BP was about 10x faster than Tesseract on CPU at about twice the error rate. On a
             GPU with batching, the CUDA-Q version should be faster still. Its accuracy should be
             similar to the CPU version, but I couldn’t measure it here.
             PyMatching is fast but a poor fit for color codes. Most error mechanisms trigger 3 to 8
             detectors, and Stim can’t break those down into the 2-detector pieces matching
             requires. I had to tell Stim to skip the ones it couldn’t break down, which accounts for
             most of PyMatching’s 7% error rate. It’s a fair baseline for showing that gap, not a
             competitive decoder here.
