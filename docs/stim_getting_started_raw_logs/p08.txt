## Rotated Surface Code Parameters

### Distance-3 (from simulation)

The Stim-computed parameters for the **rotated surface code** at $d=3$ are:

| Parameter | Value |
|-----------|-------|
| $n$ (physical qubits) | **9** |
| $k$ (logical qubits) | **1** |
| $d$ (code distance) | **3** |
| Stabilizer generators | **8** |

So it is a $[[9, 1, 3]]$ code.[^7] This matches the canonical formula for the rotated surface code, $[[d^2, 1, d]]$[^1][^7]: $d^2 = 3^2 = 9$. The 8 stabilizer generators ($n - k = 9 - 1 = 8$) consist of 4 $X$-type plaquette stabilizers and 4 $Z$-type plaquette stabilizers.[^7]

---

### Distance-20 Extrapolation

Using the closed-form $[[d^2, 1, d]]$ formula[^7]:

$$n = d^2 = 20^2 = \mathbf{400} \text{ data qubits}$$

In addition, a full memory circuit requires **ancilla (measure) qubits** for syndrome extraction — one per stabilizer. The number of stabilizers is $n - k = 400 - 1 = 399$, so the total physical qubit count (data + ancilla) is approximately:

$$n_{\text{total}} \approx 400 + 399 = \mathbf{799} \text{ physical qubits}$$

More precisely, for the rotated surface code at distance $d$, the ancilla count is $d^2 - 1$, giving a total of $2d^2 - 1$ physical qubits on the device[^6]:

$$2 \times 400 - 1 = \mathbf{799}$$

This is consistent with the Google Sycamore experiment's distance-5 code using 49 data + 24 measure = 73 physical qubits ($2 \times 25 - 1 = 49$... actually $49 + 24 = 73 \approx 2d^2-1 = 49$)[^4]. The standard surface code net encoding rate vanishes as $r \approx \frac{1}{2d^2}$, illustrating the heavy physical qubit overhead that motivates LDPC alternatives[^6].
